# UI audit 2026-10-11

Scope: every workspace at 1440×900 and 390×844, light and dark, on the
feature-complete mock model with 14 nodes and a completed automatic review;
plus the source in `web/src`. Goal: easy to understand, nothing superfluous.
Dark mode, the login screen and keyboard/ARIA basics are fine; contrast holds
in both themes. The problems are density, duplication and wording.

## Findings

| # | Area | Problem | Severity |
| --- | --- | --- | --- |
| U1 | Performance | Fourteen stacked paragraphs before the table: profile limits, review rules, quota, scope, batches, next due, decision, applied state, sample criteria. | U4 | Nodes table | Nine data columns overflow at 1440 px (Subscription is clipped). Download and Upload are two columns for one comparison; Role badges stack and double the first row's height. ## Proposal (small, separate PRs)

1. **Performance (U1).** A status grid of four tiles: *Pool* (members, verified/provisional), *Last review* (trigger, attempted/valid, MiB, decision), *Next review* (time or why deferred), *Quota* (used of limit). One status line for the current state or reason. The table. Limits and rules move into one collapsed "How reviews work". Recovery and inspection alerts stay prominent.
2. **Nodes (U2–U4).** Search plus one status chip group (All / Alive / Not alive / Not monitored / Disabled; Stale only when non-zero). Role, Source, Subscription and Country move into one "Filters" menu with an active-filter count. Selection actions appear as a labelled bar only when nodes are selected. Default columns: Name, Health, Latency, Speed (↓/↑ in one cell), Rank; Address, Role, Source, Subscription optional. Health shows "Not alive" with the error in a tooltip. Phone cards show name, health, latency and speed only.
3. **Navigation (U5).** Six items: Overview, Nodes, Performance, Configuration (tabs: Routing, DNS, All files), XKeen (components and commands), System (tabs include Backup). Distinct icons; page title equals nav label.
4. **Overview (U6).** One compact status strip (Xray, Probe, Observatory, XKeen as labelled dots), 2×2 on a phone; `·` separators; leaders table without Upload/Role on a phone.
5. **Config editor (U7, U8).** One toolbar row: Form/Text toggle, Format, Undo/Redo on the left; Reload on the right. Footer: Save and Discard; "Save all" only when more than one file changed; "Save draft" folded into the automatic working-copy behaviour or renamed "Keep draft". "Apply saved configurations" appears only when a saved change awaits Apply. DNS: drop the Router DNS card to one line; help text into a disclosure.
6. **Components and Backup (U9, U10).** One XKeen card; hide the command grid when commands are disabled; move "Panel updates" into System. Rename restore to "Restore from backup" / "Preview restore".

Each step keeps behaviour and API unchanged, updates the Playwright specs that
assert wording, and regenerates `internal/webassets/dist`. Order by value:
1, 2, 3, then 4–6 together. U11 is addressed while touching each file
(extract components; no new libraries).
