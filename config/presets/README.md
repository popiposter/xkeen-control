# Reference traffic policies

`compact-selective-v1.json` is the fresh-setup reference for Issue181. It composes the typical XKeen2.1 templates with the existing API/probe attachment and managed registry. Ordinary traffic is DIRECT; one Refilter domain and one Refilter IP category select the native balancer. Private networks/local names and BitTorrent remain DIRECT; explicit stock force-proxy policy is separate. The final selective rule excludes the probe inbound so per-node temporary rules remain reachable.

Local suffixes are the bounded public list localhost, local, lan and home.arpa; no private operator names or broad geosite categories are included. IPIfNonMatch retains the typical strategy. Already-known destination IPs can match Refilter; a final DIRECT rule may match a hostname before DNS retry, so this does not promise resolution of every hostname for IP matching. Refilter is not an exhaustive guarantee of every restriction; shared IP ranges may select unrelated hosted services. Stock XKeen owns geodata installation and updates; absent categories must fail full native validation. No custom DNS resolver, interception or DNS-over-VPN is provisioned. Existing Keenetic resolution/privacy settings remain its own authority.

The official six-template basis is upstream commit c4b0fb5b956b4f70bf1b8e4a2e0eec452d61ebd1; exact bytes/hashes are fixture data in internal/setup/testdata/typical-2.1. Fresh setup retains its existing Xray26.3.27 pin. Constructor, serving DNS and full fresh hardware acceptance are separate.

`ru-selective-v1.json` and RUSelective remain historical source compatibility data for Issue143/145; they are no longer selected by new fresh setup. Existing installations are not silently rewritten or retired. Issue181's explicit deployed migration is a separate slice.
